# 장애 사후 분석 (1장)

> [[30 Areas/Development Standard/개발 규약|개발 규약]] 12절. 버전과 변경 이력은 개발 규약 입구 문서에 둔다.

장애가 고객이나 돈에 영향을 줬으면 프로젝트 `회고/`에 한 장으로 남긴다. 탓하지 않고 구조를 고친다.

1. 무슨 일이 있었나 (언제부터 언제까지, 영향)
2. 어떻게 알았나 (알림, 고객, 우연)
3. 원인 (기술적 원인과 그것을 허용한 구조)
4. 바로 한 조치
5. 다시 안 일어나게 할 일 (담당, 기한)
6. 배운 점과 갱신할 문서(규약, 운영 절차, 결정 기록)
