# 문서 갱신

> [[30 Areas/Development Standard/개발 규약|개발 규약]] 11절. 버전과 변경 이력은 개발 규약 입구 문서에 둔다.

| 바뀐 것 | 갱신할 문서 |
|---|---|
| 되돌리기 어렵거나 다른 길을 버린 선택 | 결정 기록(ADR) 새로 쓰기. 이전 결정은 "대체됨" |
| 기능의 동작·수용 기준 | 현행 명세 저장소 `docs/specs/<도메인>.md`(같은 PR). 기능 완료 때 옵시디안 도메인 문서 `개발/도메인/<도메인>/`에 정리. 이번 변경의 무엇·왜는 기능 문서 `기능/<에픽 키> <기능>/<기능>.md` |
| 외부와의 약속(API, 메시지 형식) | `docs/interfaces/` |
| 운영 방법(배포, 장애 대응, 키 교체) | 운영 절차(`docs/runbook/` 또는 프로젝트 `개발/운영/`) |
| 구조·데이터·외부 의존 | 프로젝트 `개발/시스템 설계/`(표준 틀 4.1절) |
| 개발 규약 자체 | 개발 규약 입구 문서의 버전과 변경 이력 + 표준 틀 변경 이력 |
