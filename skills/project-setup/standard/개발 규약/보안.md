# 보안

> [[30 Areas/Development Standard/개발 규약|개발 규약]] 14절. 버전과 변경 이력은 개발 규약 입구 문서에 둔다.

## 1. 공통 규칙

**비밀정보**
- 비밀정보(키, 토큰, 비밀번호, 인증서)는 저장소·문서·로그·채팅·명령 인자에 남기지 않는다. 저장소 밖 정해진 위치에 두고 환경변수나 파일로 읽는다.
- 키는 명의자가 직접 넣는다. AI에게 실제 키와 계정 정보를 보여 주지 않는다.
- 커밋 훅과 CI에서 비밀정보 노출을 검사한다([[30 Areas/Development Standard/개발 규약/CI|6절]]). 노출되면 지우는 것으로 끝내지 않고 **키를 바로 교체**한다(Git 기록에 남는다).
- 키는 환경마다 따로 쓴다. 운영 키를 개발·검증 환경에서 쓰지 않는다.

**인증과 권한**
- 인증·권한 확인은 바깥 경계(API 진입점)에서 한다. 범위별 방식은 [[30 Areas/Development Standard/개발 규약/API|API]] 1절.
- 기본은 거부다. 권한 확인이 없는 경로는 리뷰에서 막는다.
- "내 것만" 접근하는 자원은 ID만 믿지 않고 소유자를 확인한다(다른 사람 ID로 바꿔 부르는 공격).
- 권한은 필요한 만큼만 준다: DB 역할([[30 Areas/Development Standard/개발 규약/DB|DB]]), 클라우드 계정, 외부 API 키 범위, 서버 접속.

**입력과 출력**
- 밖에서 들어온 값은 경계에서 검증한다(코드 2절 경계 검증). SQL은 파라미터 바인딩만, 셸 명령에 입력을 이어 붙이지 않는다.
- 사용자가 준 URL로 서버가 요청을 보내야 하면 허용 목록으로 제한한다.
- 오류 응답·로그에 내부 정보와 개인정보를 넣지 않는다.
- 파일 업로드는 크기·형식을 제한하고, 저장 이름은 서버가 만든다.

**개인정보**
- 수집하지 않는 것이 기본이다. 수집하면 무엇을, 왜, 얼마나 보관하는지와 지우는 방법을 시스템 설계 `보안·규정/`에 적고, 지우는 작업을 만든다.
- 개인정보는 로그·분석 도구·AI 프롬프트로 보내지 않는다. 꼭 필요하면 가린다.

**LLM·AI 기능**
- 외부에서 들어온 글(웹 페이지, 메시지, 파일)은 데이터로만 다루고 지시로 따르지 않는다.
- LLM이 실행할 수 있는 동작은 허용 목록으로 제한하고, 사람 확인 지점(발송, 돈, 삭제)은 사람이 승인한다([[30 Areas/Development Standard/개발 규약/AI 협업|AI 협업]]).

**공급망**
- 의존성은 잠금 파일로 고정하고 취약점을 검사한다([[30 Areas/Development Standard/개발 규약/의존성|의존성]]).
- CI·배포에 쓰는 외부 액션·이미지도 버전을 고정한다.

## 2. 프로젝트 셋업 때 정할 것

[[30 Areas/Development Standard/양식/프로젝트 개발 규약 양식|프로젝트 개발 규약]] 14절에 적는다.

| 항목 | 정할 내용 |
|---|---|
| 비밀정보 위치 | 환경별 위치, 넣는 사람 |
| 인증 방식 | API 범위별 |
| 권한 모델 | 역할 목록과 할 수 있는 것 |
| 개인정보 | 수집 여부, 항목, 보관 기간, 삭제 방법 |
| 법·약관 점검표 | 위치(시스템 설계 `보안·규정/`) |

## 3. 예

팀 기본값: 비밀정보는 `$SECRETS_ROOT/<프로젝트>/`, 노출 검사는 `gitleaks`.
