# 코드 컨벤션과 린트

> [[30 Areas/Development Standard/개발 규약|개발 규약]] 2절. 버전과 변경 이력은 개발 규약 입구 문서에 둔다.

## 1. 린트·포맷 공통 규칙

- **도구가 잡을 수 있는 규칙은 도구에 맡긴다.** 형식과 스타일은 리뷰에서 말하지 않는다. 문서에는 도구가 못 잡는 것만 쓴다.
- 포매터는 기본값을 거의 그대로 쓴다. 바꿀 수 있는 건 줄 길이 정도다.
- 린트 규칙 묶음에는 최소한 흔한 버그, 보안, 복잡도 상한(함수 복잡도 10, 인자 5개), import 규칙(상대 import 금지)이 들어간다. 다른 절을 지키게 하는 규칙(레이어, 시간대, 보안, 비밀정보)은 끄지 않는다.
- 설정은 저장소의 설정 파일 한 곳에 둔다. 문서에 설정을 복사하지 않는다.
- **세 시점에서 돈다.**
  - 저장할 때: 편집기에서 포맷.
  - 커밋할 때: 몇 초 안에 끝나는 것만(포맷, 린트 자동 수정, 비밀정보 검사). 타입 검사와 테스트는 넣지 않는다.
  - PR 때: 전체([[30 Areas/Development Standard/개발 규약/CI|CI]]).
  - AI 작업자는 파일을 고친 직후 포맷과 린트를 돌린다(에이전트 훅).
- **규칙 끄기.** 한 곳만 끌 때는 그 자리에 규칙 코드와 이유를 쓴다(코드 없이 전부 끄지 않는다). 규칙을 통째로 끄면 설정 파일 주석과 PR에 이유를 남긴다. 기존 코드에 처음 넣어 위반이 많으면 그 규칙만 잠시 끄고 정리 티켓을 만든다.

## 2. 공통 컨벤션 (언어와 상관없음)

모든 프로젝트가 그대로 따른다. 언어 관례와 부딪히면 언어 관례가 이기고, 그 차이는 프로젝트 개발 규약 2절에 적는다.

**이름**

| 대상 | 규칙 | 예 |
|---|---|---|
| 일반 | 줄이지 않는다. 널리 쓰는 줄임말(`id`, `url`, `api`)만 허용 | `user_count` (`usr_cnt` 아님) |
| 단위 | 값에 단위가 있으면 이름 끝에 붙인다 | `price_won`, `timeout_s`, `size_bytes`, `ratio_pct` |
| 참·거짓 | `is_`·`has_`·`can_`·`should_`로 시작한다. 부정형 이름은 쓰지 않는다 | `is_active` (`is_not_deleted` 아님) |
| 함수 | 동사로 시작한다. 조회는 `get_`(없으면 오류) / `find_`(없으면 빈 값), 만들기 `create_`, 바꾸기 `update_`, 지우기 `delete_` | `find_user_by_email` |
| 컬렉션 | 복수형 | `users`, `order_ids` |
| 시각·날짜 | 시각은 `_at`, 날짜는 `_on`, 기간은 단위 | `created_at`, `due_on`, `ttl_s` |
| 도메인 용어 | 도메인 문서의 용어를 코드·API·DB에서 같은 단어로 쓴다. 한 개념에 이름 하나 | 기획이 "대여"면 코드도 `rental` |
| 파일·폴더 | 한 파일은 한 가지 책임. 파일 이름은 그 책임 | `rental_policy.py` |

**값 표현**

| 대상 | 규칙 |
|---|---|
| 돈 | 최소 단위 정수(원). 부동소수점으로 계산하지 않는다. 통화가 둘 이상이면 금액과 통화 코드(ISO 4217)를 함께 둔다 |
| 시각 | `domain`·`app`은 현재 시각을 직접 읽지 않고 호출자가 넘긴 `now` 인자를 쓴다(공급은 `platform`/`main`). 저장·계산·전송은 UTC, 시간대를 포함한다. 문자열은 ISO 8601(`2026-11-07T03:00:00Z`). 화면에 보일 때만 현지 시간으로 바꾼다 |
| 날짜만 | `YYYY-MM-DD`. 어느 시간대 기준 날짜인지 이름이나 문서에 밝힌다 |
| ID | 밖에 노출되는 ID는 추측할 수 없는 값(UUID 등). 순번 ID를 URL에 내보내지 않는다 |
| 상태값 | 정해진 목록(enum)으로. 자유 문자열로 상태를 표현하지 않는다. 저장값은 소문자 영어(`pending`, `done`) |
| 빈 값 | "없음"과 "빈 값"을 구분한다. 목록은 없음 대신 빈 목록을 돌려준다 |

**오류 처리**

- 프로젝트 기반 오류 하나에 오류 코드([[30 Areas/Development Standard/개발 규약/API|API]]의 코드 체계)를 담는다. 도메인 오류는 이것을 상속(또는 감싼다)한다.
- 바깥 경계(API 입력, 외부 호출, 예약 작업, 메시지 소비)에서 잡고 기록한다. 안쪽은 그대로 올린다.
- 조용히 삼키지 않는다. 잡았으면 기록하거나, 바꿔서 다시 올리거나, 복구 방법이 코드에 있어야 한다.
- 외부 호출에는 항상 타임아웃을 둔다. 재시도는 멱등한 호출에만, 횟수 상한과 대기 시간 증가(backoff)를 둔다.
- 사용자에게 보이는 오류 문구에는 내부 정보(스택, SQL, 경로)를 넣지 않는다.

**경계 검증**

- 밖에서 들어오는 값(API 입력, 외부 응답, 파일, 설정, 환경변수)은 경계에서 한 번, 타입이 있는 모델로 검증한다. 안쪽은 검증된 타입을 믿고 다시 검사하지 않는다.
- 설정은 시작할 때 전부 검증하고, 빠졌거나 틀리면 바로 멈춘다.

**로그**

- `domain`·`app`은 표준 라이브러리 `logging`으로 남긴다. 출력 형식·핸들러 설정은 `platform`/`main`이 한 번 정하고, `app`이 `platform`을 import해 로그를 설정하지 않는다.
- 구조화된 한 줄(JSON). 필수 필드: `ts`(UTC), `level`, `event`(`<도메인>.<무엇>.<결과>`, 예: `rental.reserve.failed`), `request_id`, 관련 ID.
- 수준: `ERROR` 사람이 봐야 함(알림 대상), `WARNING` 이상하지만 처리됨, `INFO` 상태가 바뀐 업무 사건, `DEBUG` 운영에서는 끔.
- 비밀정보·토큰·개인정보(이메일, 전화, 주소)는 남기지 않는다. 필요하면 가리거나 해시로.
- `request_id`는 들어온 요청에서 받거나 만들고, 이후 외부 호출·로그·오류 응답에 그대로 넘긴다.

**설정·비밀**

- 설정 순서: 코드 기본값 < 환경별 파일 < 환경변수.
- 환경변수 이름: `<프로젝트 접두어>_<무엇>` 대문자(`BOOK_DB_URL`).
- 환경 이름은 `dev`, `test`(검증), `prod` 셋 중에서 쓴다.
- 비밀정보는 저장소 밖에 둔다. 저장소의 예시 파일(`.env.example`)에는 이름만 쓴다.
- 기능 켜고 끄기(feature flag)는 설정으로 하고 이름은 `FEATURE_<무엇>`, 기능이 자리잡으면 플래그와 분기를 지운다.

**주석·할 일**

- 코드로 안 보이는 "왜"만 한 줄로 쓴다. 무엇을 하는지는 이름으로 드러낸다.
- 알려진 한계는 `shortcut: <한계>, <언제 바꿀지>`.
- 할 일은 `TODO(<티켓 키>): <내용>`. 티켓 키 없는 TODO는 쓰지 않는다.
- 주석 처리한 코드는 남기지 않는다(Git에 있다).

**크기**

- 함수 복잡도 10, 인자 5개를 넘지 않는다(린터로 검사). 넘으면 묶을 값 객체를 만든다.
- 파일이 400줄을 넘으면 나눌지 검토한다.

## 3. 프로젝트 셋업 때 정할 것

모듈 언어마다 [[30 Areas/Development Standard/양식/프로젝트 개발 규약 양식|프로젝트 개발 규약]] 2절에 적는다.

| 항목 | 정할 내용 |
|---|---|
| 포매터 | 도구 |
| 린터 | 도구, 설정 파일 위치, 1장 기준 외에 더하거나 뺀 규칙과 이유 |
| 타입 검사 | 도구, 엄격도 |
| 커밋 훅 | 도구, 넣을 검사 |
| 에이전트 훅 | AI 작업자가 수정 직후 돌릴 명령 |
| 언어 관례 차이 | 2장과 다르게 하는 것(예: Swift는 `camelCase`) |
| 값 | 기반 오류 이름, 환경변수 접두어, 비밀정보 위치 |

## 4. 예

- 팀 기본값(Python 서비스, [[30 Areas/Development Standard/프로젝트 표준 틀|표준 틀]] 6절): 포맷 `ruff format`, 린트 `ruff check`, 타입 `pyright`, 커밋 훅 `pre-commit`(ruff, gitleaks). 설정은 각 저장소 `pyproject.toml`.
- Swift: `swift format`(툴체인 내장). TS·JS: Biome(포맷과 린트를 한 도구로).
