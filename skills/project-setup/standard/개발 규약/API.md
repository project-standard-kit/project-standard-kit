# API

> [[30 Areas/Development Standard/개발 규약|개발 규약]] 3절. 버전과 변경 이력은 개발 규약 입구 문서에 둔다.

## 1. 노출 범위

API는 누가 부르느냐에 따라 나누고, 범위마다 약속의 무게가 다르다. 한 경로는 범위 하나에만 속한다.

| 범위 | 누가 부르나 | 인증 | 호환성 약속 | 문서 |
|---|---|---|---|---|
| 퍼블릭 | 불특정 다수(공개 API, 공개 페이지용) | 없음 또는 발급 키. 속도 제한 필수 | 가장 무겁다. 깨는 변경은 새 버전 + 폐기 공지 기간 | 외부 공개 |
| 외부 연동 | 정해진 파트너·외부 플랫폼(웹훅 수신 포함) | 상대별 키 또는 서명 검증, 가능하면 IP 제한 | 무겁다. 상대와 합의한 일정으로만 바꾼다 | 상대에게 공유 |
| 클라이언트 | 우리 앱·웹 화면 | 사용자 인증(세션·토큰) | 중간. 배포된 앱 버전이 남아 있는 동안 유지 | 저장소 |
| 내부 | 우리 서비스끼리 | 서비스 인증, 외부망에 열지 않음 | 가볍다. 호출하는 쪽과 같이 바꿀 수 있으나 배포 순서를 지킨다 | 저장소 |
| 관리자 | 운영 도구, 운영자 | 강한 인증 + 권한 확인, 모든 변경을 감사 로그로 남김 | 가볍다 | 저장소 |

- 경로 앞에 범위를 드러낸다: `/public`, `/partner`, (클라이언트는 접두어 없음), `/internal`, `/admin`. 또는 범위마다 다른 호스트를 쓴다. 어느 쪽인지는 프로젝트가 정한다.
- 범위가 다른 API는 인증 미들웨어를 따로 건다. 한 핸들러가 두 범위를 함께 받지 않는다.
- 내부·관리자 API는 외부에서 닿지 않게 네트워크에서도 막는다. 인증만 믿지 않는다.

## 2. 도메인으로 묶기

- API는 도메인([[30 Areas/Development Standard/프로젝트 표준 틀|표준 틀]] 4.3절) 단위로 묶는다. 한 경로는 도메인 하나에 속하고, 그 도메인의 `app`만 부른다.
- 경로: `/<범위>/v<버전>/<도메인 자원>/...` (예: `/v1/rentals/{rental_id}`, `/admin/v1/rentals`).
- 오류 코드 접두어는 도메인 접두어다: `RENTAL_1001`. 접두어 목록은 프로젝트 도메인 목록에 둔다.
- 계약 문서도 도메인마다: 저장소 `docs/interfaces/<도메인>.md`(또는 OpenAPI의 태그 = 도메인).
- 여러 도메인을 모아 보여 주는 화면용 API가 필요하면, 그 조합은 화면 쪽 `app`(또는 BFF)이 하고 도메인 API를 부른다. 도메인 API가 다른 도메인 데이터를 섞어 돌려주지 않는다.

## 3. 공통 형식

| 항목 | 규칙 |
|---|---|
| 경로 | 명사 복수, 소문자와 하이픈(`/v1/price-alerts`). 동작은 HTTP 메서드로 표현한다. 동사가 꼭 필요하면 `:<동사>`(`/v1/rentals/{id}:cancel`) |
| 메서드 | `GET` 조회(부작용 없음), `POST` 생성·동작, `PUT` 통째 교체, `PATCH` 일부 수정, `DELETE` 삭제 |
| 필드 이름 | JSON은 `snake_case`. 시각은 ISO 8601 UTC, 돈은 정수 최소 단위([[30 Areas/Development Standard/개발 규약/코드\|2절]] 공통 컨벤션) |
| 버전 | 경로의 `v1`. 호환이 깨지면 `v2`를 새로 연다. 필드 추가는 호환 변경, 필드 삭제·이름·타입·의미 변경은 깨는 변경 |
| 성공 응답 | 본문이 곧 결과 객체(감싸지 않음). 생성은 `201`과 만든 객체 |
| 목록 | `{"items": [...], "next_cursor": "..." \| null}`. 커서 방식, `limit` 기본 20·최대 100 |
| 오류 응답 | 한 가지 형식: `{"error": {"code": "RENTAL_1001", "message": "...", "request_id": "..."}}`. `message`는 사용자에게 보여도 되는 문장 |
| 상태 코드 | `400` 입력 형식 오류, `401` 인증 없음, `403` 권한 없음, `404` 없음, `409` 상태 충돌, `422` 업무 규칙 위반, `429` 속도 제한, `500` 서버 오류, `503` 의존 서비스 장애 |
| 오류 코드 | `<도메인 접두어>_<4자리>`. 앞자리: 1 입력·규칙, 2 상태·충돌, 3 권한, 5 외부 의존, 9 내부. 목록은 저장소 `docs/interfaces/error-codes.md` 한 곳. 화면 쪽은 코드별 공통 처리(재시도·안내 문구·로그인 이동)를 한 곳에서 한다 |
| 요청 ID | 요청 헤더 `X-Request-Id`를 받거나 만들고, 응답 헤더와 오류 본문에 돌려준다 |
| 시간 제한 | 모든 외부 호출에 타임아웃을 명시한다. 기본값을 믿지 않는다 |
| 재시도·멱등 | 재시도할 수 있는 `POST`는 `Idempotency-Key` 헤더를 받아 같은 키면 같은 결과를 돌려준다 |
| 속도 제한 | 퍼블릭·외부 연동은 필수, 초과 시 `429`와 `Retry-After` |
| 상태 확인 | `GET /health`(프로세스만, 인증 없음), `GET /internal/health/ready`(DB·필수 외부 의존) |
| 웹훅 수신 | 서명 검증 → 즉시 `2xx` → 처리는 비동기. 같은 이벤트가 두 번 와도 한 번만 처리(이벤트 ID로) |

## 4. 계약과 변경

- 이 모듈이 다른 곳에 약속하는 형식은 저장소 `docs/interfaces/`에 둔다. API·오류 코드가 바뀌면 같은 PR에서 고치고, 배포 기록에 바뀐 목록을 적는다([[30 Areas/Development Standard/개발 규약/배포|배포]]).
- 깨는 변경은 퍼블릭·외부 연동·클라이언트 범위에서 하지 않는다. 새 버전을 열고, 옛 버전은 폐기 공지 후 호출이 없음을 확인하고 닫는다.

## 5. 프로젝트 셋업 때 정할 것

[[30 Areas/Development Standard/양식/프로젝트 개발 규약 양식|프로젝트 개발 규약]] 3절에 적는다.

| 항목 | 정할 내용 |
|---|---|
| 쓰는 범위 | 다섯 범위 중 이 프로젝트에 있는 것, 범위별 경로 접두어 또는 호스트 |
| 범위별 인증 | 방식(세션, 토큰, 키, 서명, 서비스 인증) |
| 폐기 공지 기간 | 퍼블릭·외부 연동·클라이언트 각각 |
| 속도 제한 | 범위별 기준 |
| 도메인 접두어 | 도메인 목록에 경로 자원 이름과 오류 코드 접두어 |
| 계약 형식 | Markdown 표 / OpenAPI 등 |
