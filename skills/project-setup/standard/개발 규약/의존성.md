# 의존성

> [[30 Areas/Development Standard/개발 규약|개발 규약]] 9절. 버전과 변경 이력은 개발 규약 입구 문서에 둔다.

## 1. 공통 규칙

- 잠금 파일로 모든 버전(간접 의존 포함)을 고정하고 저장소에 넣는다. 배포·CI는 잠금 파일을 바꾸지 않고 그대로 설치한다.
- 새 패키지를 넣을 때는 PR에 이유를 한 줄 남긴다. 표준 라이브러리로 몇 줄이면 되는 일에는 넣지 않는다.
- 넣기 전에 본다: 관리가 살아 있나(최근 릴리스), 라이선스가 쓸 수 있는 것인가, 의존을 얼마나 끌고 오나.
- 업데이트는 한 달에 한 번 묶어서 하고, 업데이트 PR은 기능 변경과 섞지 않는다.
- 취약점 경고는 심각도 높음 이상이면 바로 처리한다. 당장 못 고치면 이유와 기한을 티켓으로 남긴다.

## 2. 프로젝트 셋업 때 정할 것

[[30 Areas/Development Standard/양식/프로젝트 개발 규약 양식|프로젝트 개발 규약]] 9절에 적는다.

| 항목 | 정할 내용 |
|---|---|
| 도구 | 패키지 관리 도구, 잠금 파일 |
| 취약점 검사 | 도구(CI 진입점에 포함) |
| 자동 업데이트 | 쓰나(Renovate·Dependabot 등), 주기 |

## 3. 예

팀 기본값: `uv` + `uv.lock`, 배포는 `uv sync --frozen`, 취약점은 `pip-audit`.
